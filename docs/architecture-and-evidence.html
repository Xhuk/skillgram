Why We Stopped Linking 800 Skills Everywhere—and Built a Self-Curating Skill Hub

What happens when you use Claude Code, Codex, Cursor, Gemini, and OpenCode on the same machine? A candid look at our architecture, the hypotheses we tested, real telemetry from our workstations, and an invitation to try skillgram on yours.

skillgram 1.10 Python 3.9+ · stdlib only Windows junctions · POSIX symlinks · MCP stdio

1. The Fallacy vs. The Real Pain

When we started skillgram, our initial hypothesis was simple: "Keep one copy of every SKILL.md in ~/.agents/skills and link all of them into every coding agent." After living with 861 skills (89 MB) across 11 agent harnesses on Windows and Linux, we learned a hard truth:

The Fallacy: Saving SSD Megabytes 800 Markdown files take ~89 MB on disk. Saving megabytes on a modern SSD is not why you need a skill manager.
Pain #1: Context Rot (Token Bloat) Exposing 861 skills globally injects ~45,000 tokens of descriptions into every agent's system prompt on every session—degrading reasoning and routing accuracy.
Pain #2: Recursive Double-Loading Modern harnesses scan skills/ recursively. Linking both skills/<category> and skills/<skill> caused agents to load every skill twice (1,722 entries).
Pain #3: Untested Third-Party Slop Public skill directories are full of bloated, untested Markdown that collides with existing triggers or hides unsafe shell instructions.
Our thesis in 1.10: Disk links are for Single Source of Truth (fix a skill in Claude Code, and Codex/Cursor/Gemini immediately read the fix). Context is protected by Tiered Visibility (only seeds globally, project manifests per repo, and zero-token lazy reading via MCP).

3. Use Cases We Designed & Tested

Use Case A — Testing Third-Party Skills Without Polluting Your Workspace

Most developers do not write SKILL.md files from scratch—they discover skills like impeccable (UI craft) or dokploy (deployment) on GitHub and want to test them and pull upstream updates safely.

Because every skill is domain-specific, you cannot write one generic unit test for all of them. Instead, skillgram combines a deterministic Admission Gate with a disposable git worktree Trial: 

# 1. Stage a third-party skill (or an upstream update) in a detached git worktree of your repo
python skillgram.py try https://github.com/author/impeccable --project ~/projects/my-next-app

# 2. Test it with your agent inside the isolated worktree, then either seal or discard:
python skillgram.py try impeccable --accept    # records upstream URL, commit SHA & verified hash
python skillgram.py try impeccable --reject    # removes the worktree and staging cleanly

Use Case B — Organic Curation: Let the LLM & Project Stack Vote

How do you know which skills actually work across hundreds of candidates? Real usage and survival.

  • Local Absorption: If you or npx skills add drop a skill directly into <repo>/.claude/skills/, running skillgram adopt --project . moves it into the Hub, leaves a junction in place, adds it to the repo manifest, and tags it with the repo's deterministic stack signals (repo_signals(): e.g. next, tailwind, docker).
  • Stack-Affinity Ranking: Every time an agent promotes (skillgram_use), reads (skillgram_read), or touches (skillgram_touch) a skill, the Hub increments usage.stack_hits for that repository's tags in SKILLMETA.json.
  • Survival vs. Removal: If you keep the skill across projects, its score for that stack rises. If it is noisy and you run skillgram unuse <skill>, unuse_count penalizes it. Next time you bootstrap a repo with the same stack, proven skills rank first—even if their markdown never mentions your framework by name.

5. Companion Ecosystem: skillgram + EdgePass

Managing an AI coding workstation has two halves: what your agents know (skills & instructions) and what your agents can execute and access (secrets, MCP daemons, tunnels, and local CI runners). We built skillgram and EdgePass so each lives cleanly on its own—zero hard dependency on the other—while snapping together automatically when both are present on the same machine:

Standalone: skillgram CLI + MCP server for SKILL.md governance: hub deduplication, contract & security gate, worktree trials, stack-affinity ranking, and zero-token vaulting.
Standalone: EdgePass Native desktop notch widget & control plane that injects OpenBao secrets into processes without exposing plaintext tokens in agent configs or logs, plus live LEDs for MCP servers and local GitHub Actions runners.
Connected via skillgram daemon EdgePass speaks to skillgram daemon over a local JSON-line pipe ({"op": "status"}, {"op": "sync"}) to surface real-time skill drift on a desktop LED and sync all harnesses in one click.
Discover the other half of the stack: Visit xhuk.github.io/edgePass or the EdgePass GitHub repository (installable via winget install Xhuk.EdgePass) to see how secret injection, MCP health, and local runner supervision pair with skillgram.

6. Try It on Your Machine & Share Your Telemetry

If you run two or more coding agents (Claude Code, Codex, Cursor, Gemini CLI, OpenCode, Windsurf, Aider), you can audit your current skill footprint in 60 seconds with zero external dependencies (Python 3.9+ stdlib only): 

git clone https://github.com/Xhuk/skillgram
cd skillgram

# 1. See how many harnesses, native copies, and collisions you have right now:
python skillgram.py doctor

# 2. Measure duplicated bytes and 0-hit skills (dry-run, touches nothing):
python skillgram.py compact --vault-unused

# 3. Audit any skill's token cost, security, and trigger collisions:
python skillgram.py gate <path-to-any-skill>

# 4. Reclaim space, vault unused skills, and link only your seeds globally:
python skillgram.py compact --vault-unused --apply --purge-quarantine
python skillgram.py sync --seeds-only

Help us gather field evidence: Run python skillgram.py compact --vault-unused --json on your machine and share the JSON summary (or open a report with skillgram-report) in GitHub Issues.
